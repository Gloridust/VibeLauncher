# 真实账号检查（macOS / Windows）

CI 每次都用替身应用把命令行流程和窗口操作跑一遍，但替身不会登录。真实的 Claude、ChatGPT 桌面版登录只能在真机上用真实账号验证。每台机器大约 10 分钟。

准备：装好官方 Claude 和/或 ChatGPT 桌面版，平时的账号已登录（那就是“原样运行”的默认配置）；再准备一个**另外的**账号用来测试独立配置。

## 1. 新建与隔离

- [ ] 打开 VibeLauncher，侧栏能看到 Claude（和 ChatGPT），状态与实际一致（开着的显示“运行中”）。
- [ ] 新建配置 “Test”（Claude），打开它：出现一个**全新、未登录**的 Claude 窗口，原来的 Claude 窗口不受影响、仍是原账号。
- [ ] 两个窗口能同时开着；VibeLauncher 里两者都显示“运行中”。

## 2. 登录（最关键的一项）

- [ ] 在 “Test” 上点 **登录…**，在弹出的 Claude 窗口里点登录，浏览器打开。
- [ ] 用测试账号完成登录，浏览器问“打开 Claude？”时允许。
- [ ] 链接回到 **“Test” 这个窗口**并登录成功；VibeLauncher 的登录面板显示“已转交登录链接”；原来的 Claude 仍是原账号。
- [ ] 诊断 → “最近的链接” 里有这条记录，**看不到登录码**。
- [ ] 如果链接没回来：在浏览器里复制“打开 Claude”按钮的链接，粘到面板里，能完成登录。（顺便记下链接为什么没回来。）
- [ ] 关掉 “Test” 再打开：仍是登录状态。
- [ ] ChatGPT 同样走一遍（链接是 `codex://`）。

## 3. 更新与恢复

- [ ] 设置 → 转发链接：显示“由 VibeLauncher 处理”。关掉开关后，`claude://` 链接直接交给 Claude（可以在浏览器地址栏输入 `claude://` 试）；再打开恢复。
- [ ] 删除 “Test”（勾上“同时把数据移到废纸篓”）：窗口先退出，配置消失；只剩一个 Claude 配置时，设置里显示“暂不需要”，`claude://` 已还给 Claude。
- [ ] 官方应用自动更新后（或手动装新版），独立配置仍能打开、仍是登录状态；如果更新让它以共享设置重启了，侧栏会标“未隔离”，点“重新启动”能恢复。

## 4. 安装包

- [ ] macOS：从 `.dmg` 拖进“应用程序”，能打开（未签名时右键“打开”）；“快捷方式”开关会在 `~/Applications/VibeLauncher` 生成 “Claude · Test”，从启动台/聚焦能打开到对应配置。
- [ ] Windows：安装器能装（未签名时 SmartScreen 选“仍要运行”）；“快捷方式”会出现在开始菜单；卸载后快捷方式与链接处理都清理掉（CI 用替身应用检查过安装、升级、卸载，这里确认真实应用也一样）。
- [ ] macOS：路由开着时**不运行** `vibelauncher cleanup`，直接把 VibeLauncher 拖进废纸篓并清空；再在浏览器里打开一个 `claude://` 链接，应当直接打开 Claude（CI 只检查过路由脚本能编译，转交给应用本身要在真机上看）。之后把这台机器上的 VibeLauncher 装回来。

发现问题请开 issue，附上系统版本、应用版本、`vibelauncher doctor` 的输出和 `vibelauncher log` 的最后几行（这两项都不含登录码）。
